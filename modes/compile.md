# Compile

Goal: the project's final deliverable, assembled from records, with every claim traceable to a record.

- P1. Run `python3 <skill-dir>/scripts/check_records.py <project-root>` and fix every error in the records first. Never repair gaps only in the final deliverable.
- P2. Fix the experience frame, form, scope, and destination: which current W records and volumes are included, and the output form (for example a specification with manual and report, a paper, a slide deck with notes, or a findings report). Default: `docs/COMPILED.md` in Markdown unless the operator names a path or format.
- P3. What it is: per work unit, Intent, How, interfaces or structure, and constraints from D records; Locators as an appendix table.
- P4. How to use it: Use fields grouped by the reader's tasks; Limits as caveats.
- P5. How it came to be: per volume in order, phase objective, comparisons with results, decisions with alternatives and evidence, verification evidence, exit summary; then open deferred items.
- P6. Verify a sample of claims, and every numeric claim, against the artifacts at their locators.
- P7. Run the generic-feel review in [craft](../references/craft.md), including the independent delegate review for this high-stakes deliverable, and pass the output checks.
- P8. Tag each section with its source IDs (e.g. `[W-012, D-004]`) so the deliverable can be regenerated.
