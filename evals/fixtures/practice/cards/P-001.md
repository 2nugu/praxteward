# P-001 — Data store selection

- **Version:** 1.1
- **Status:** standard
- **Kind:** method
- **Scope:** general
- **Task type:** choose persistent storage
- **Objective:** keep data intact and operating cost low for the real access pattern
- **Applies when:** data must persist; the storage choice is being made or revisited
- **Not when:** throwaway prototypes with no data worth keeping
- **Decision factors:** write concurrency, deployment topology, operational effort, migration cost
- **Procedure:**
  1. Measure the actual access pattern and peak write rate.
  2. List viable stores, including keeping the current one.
  3. Compare on the decision factors with numbers.
  4. Record the decision with its reversal condition.
- **Verification:** concurrent write test passes; integrity check clean after a crash test
- **Assumptions:**
  - peak writes stay under 10 per second — measure from production logs monthly
- **Review triggers:** a second writer process appears; data grows tenfold; review_by: 2027-04-30
- **Simpler alternative:** keep SQLite with WAL — failed the concurrent write test at 40 writes per second
- **Transfer:** concurrent writers corrupt shared state → several writers, durability required → serialize writes through a transactional store → concurrent write test
- **Automation:** decision rule — about 10 decisions a year, 30 minutes saved each, low failure cost
